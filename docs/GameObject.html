全体像

GameObject は「Transform（位置・回転・スケール）を持つ器」で、 そこに IComponent を継承した「機能」を後付けでアタッチしていく設計です。 Unity の GameObject + Component にヒントを得ていますが、 このプロジェクトの規模（学校課題のゲームロジック層）に合わせて、かなり軽量に作ってあります。

GameObject ├─ transform (Transform型を直接保持。scale / rotation / translation) ├─ name (ImGui・ギズモの表示名にそのまま使われる) └─ components_ (std::vector<unique_ptr<IComponent>>) └─ 例: CubeRenderComponent ← RenderComponentBase ← IComponent SphereRenderComponent TriangleRenderComponent ModelRenderComponent (Model / FBXModel 共用) SpriteRenderComponent (Sprite3D / Sprite2D 共用)

設計方針は一貫して「継承は最小限、コンポーネントは軽量なコンポジション」です。 IComponent は仮想関数 Update(float) ひとつだけの薄い抽象クラスで、 型を跨いだ動的検索（Unity の GetComponent<T>() のような RTTI 探索）は GameObject::GetComponent<T>() として存在しますが、実装は単純な線形探索です。 オブジェクト数・コンポーネント数が少ない今の規模ではこれで十分という判断です。

クラス構成

GameObject（Engine/GameObject/GameObject.h）

class GameObject {
public:
    Transform   transform;   // 位置・回転・スケール。必須フィールドなのでコンポーネント化しない
    std::string name;        // ImGui / ギズモの表示名

    template<typename T, typename... Args>
    T* AddComponent(Args&&... args);   // コンポーネントを追加し、生ポインタを返す

    template<typename T>
    T* GetComponent();               // 型で検索して取り出す（線形探索）

    void Update(float deltaTime); // 全コンポーネントのUpdateを順番に呼ぶ
};

IComponent（Engine/GameObject/IComponent.h）

class IComponent {
public:
    virtual ~IComponent() = default;
    virtual void Update(float deltaTime) { }
};

描画コンポーネントは Update() を使わず、独自の Draw(Renderer*, ...) メソッドを 直接呼ぶ運用です（下記「クイックスタート」参照）。IComponent::Update は将来 「移動する」「アニメーションする」のような、描画以外のふるまいを追加したくなったときの拡張ポイントです。

RenderComponentBase（Engine/GameObject/Component/RenderComponentBase.h）

Cube / Sphere / Triangle / Model / Sprite が共通して持つ「色・ライティング・テクスチャ・ ブレンドモード・アルファテスト」の7プロパティをまとめた基底クラスです。 

class RenderComponentBase : public IComponent {
public:
    Vector4       color          = { 1, 1, 1, 1 };
    bool          lighting       = true;
    TextureHandle textureHandle  = kTextureNone;
    BlendMode     blendMode      = BlendMode::kNone;
    float         blendStrength  = 1.0f;
    bool          alphaTest      = false;
    float         alphaThreshold = 0.5f;
};
コンポーネント継承元用途固有メンバ
CubeRenderComponentRenderComponentBaseCube / Floor（同じクラスを使い回す）なし
SphereRenderComponentRenderComponentBaseSphereなし
TriangleRenderComponentRenderComponentBaseTriangleなし
ModelRenderComponentRenderComponentBaseModel(OBJ) / FBXModel（同じクラスを使い回す）modelHandle, hasAnimation
SpriteRenderComponentRenderComponentBaseSprite3D / Sprite2D（同じクラスを使い回す）is3D, uvTransform
使い回しのコツ：プロパティ構成が同じオブジェクト同士（Cube と Floor、 Model と FBXModel、Sprite3D と Sprite2D）は、新しいクラスを作らず 同じコンポーネント型を2つ目の GameObject インスタンスに付けるだけで済みます。 「オブジェクトの種類」ではなく「コンポーネントの構成」で再利用を考えるのがコツです。

最短の使い方

実際に Game.cpp で Cube を1個扱っているコードそのままの例です。3ステップで完結します。

1Initialize() でオブジェクトを作る

GameObject cubeObject_;  // Game.h側でメンバとして持っておく

// Game::Initialize() 内
cubeObject_.name = "Cube";
cubeObject_.transform.translation = { -3.0f, 1.0f, 0.0f };

CubeRenderComponent* cubeRender = cubeObject_.AddComponent<CubeRenderComponent>();
cubeRender->textureHandle = textures_[cubeTexIndex_].handle;
cubeRender->color         = { 1, 1, 1, 1 };
cubeRender->lighting      = true;

2Render() で描画する

// Game::Render() 内
cubeObject_.GetComponent<CubeRenderComponent>()->Draw(renderer_, cubeObject_.transform);

Draw() の中身は各コンポーネントが持っていて、実際には renderer->DrawCube(transform, color, textureHandle, lighting, blendMode, blendStrength, alphaTest, alphaThreshold) を呼んでいるだけです。既存の Renderer のAPIは一切変更していません。

3DrawImGui() でプロパティを触れるようにする

// Game::DrawImGui() 内
CubeRenderComponent* cubeRender = cubeObject_.GetComponent<CubeRenderComponent>();
ImGui::Checkbox("Cube Lighting", &cubeRender->lighting);
ImGui::ColorEdit4("Cube Color", &cubeRender->color.x);
ImGui::DragFloat3("Cube Translation", &cubeObject_.transform.translation.x, 0.01f, -10.0f, 10.0f);
// テクスチャ選択やBlendMode選択も同様に cubeRender->xxx を直接触る
注意：GetComponent<T>() は「そのコンポーネントが必ずアタッチ済み」という前提で 生ポインタを返します（nullptr チェックはしていません）。 Initialize() で AddComponent を呼び忘れると、 Render() や DrawImGui() でのアクセス時にクラッシュします。

既存コンポーネント一覧と使い分け

ModelRenderComponent（ModelHandle が必要なもの用）

Model(OBJ) と FBXModel はどちらも Renderer::LoadModel(dir, filename) で得られる ModelHandle を必要とするため、コンストラクタで受け取ります。 FBXModel のようにボーンアニメーションを持つ場合は hasAnimation = true にすると、 Draw() 内で毎フレーム UpdateModelAnimation を自動的に呼びます。 

ModelRenderComponent* modelRender = modelObject_.AddComponent<ModelRenderComponent>(
    renderer_->LoadModel("Resources/Model", "player.obj"),
    /*hasAnimation=*/false);

ModelRenderComponent* fbxRender = fbxModelObject_.AddComponent<ModelRenderComponent>(
    renderer_->LoadModel("Resources/Model", "HumanModel_ver2.fbx"),
    /*hasAnimation=*/true);

// Render() 側は deltaTime を渡すだけで、アニメ更新の有無はコンポーネントが判断してくれる
modelObject_.GetComponent<ModelRenderComponent>()->Draw(renderer_, modelObject_.transform, deltaTime_);

SpriteRenderComponent（UVTransform が必要なもの用）

Sprite3D と Sprite2D はどちらも UVTransform（UVのオフセット・回転・スケール）を持ちます。 is3D フラグで、内部的に DrawSprite3D と DrawSprite2D の どちらを呼ぶかが自動的に切り替わります。 

SpriteRenderComponent* sprite3DRender = sprite3DObject_.AddComponent<SpriteRenderComponent>(/*is3D=*/true);
SpriteRenderComponent* sprite2DRender = sprite2DObject_.AddComponent<SpriteRenderComponent>(/*is3D=*/false);
sprite2DRender->lighting = false; // Sprite2Dはデフォルトでライティングなし

// UVTransformはコンポーネントのメンバとして直接触れる
sprite3DRender->uvTransform.offset = { 0.1f, 0.0f };
グローバル設定は据え置き：cubeSmoothness_（Cubeの丸み）、 sphereSubdivision_（Sphereの分割数）、triangleSmoothness_ は Renderer::SetCubeSmoothness() のような「シーン全体に効くグローバル設定」であり、 個体ごとのプロパティではないため、意図的にコンポーネントへ持たせず Game.h 側に残しています。

新しいコンポーネントを作る手順

「Cube のような単純な描画物を1つ増やしたい」場合は、既存の CubeRenderComponent を そのまま再利用できないか、まず検討してください。プロパティ構成（色・ライティング・テクスチャ・ BlendMode・AlphaTest の7つだけ）が同じなら、新規クラスは不要です。

それでも新しいコンポーネントが必要な場合の型どおりの手順です（例：XxxRenderComponent）。

  1. Engine/GameObject/Component/XxxRenderComponent.h を作り、 RenderComponentBase を継承。固有のパラメータ（ハンドルやUVなど）があれば コンストラクタ引数かメンバとして追加する。
  2. .cpp 側で Draw(Renderer*, const Transform&, ...) を実装し、 対応する renderer->DrawXxx(...) を1回呼ぶだけにする。
  3. .vcxproj と .vcxproj.filters の ClCompile / ClInclude にフラットに1行ずつ追記する（フィルタ指定は不要）。
  4. Game.h に GameObject xxxObject_; を追加し、 Game::Initialize() で AddComponent、 Game::Render() で Draw() を呼ぶ。
  5. ギズモ操作対象にしたい場合は、Initialize() 末尾の gizmoTargets_ = { ... } に &xxxObject_ を追加するだけでよい （下記「ギズモとの連携」参照）。

ギズモ（ImGuizmo）との連携

Blender 風の移動・回転・拡大縮小ギズモは GameObject::transform への生ポインタを 受け取って直接書き換えるだけなので、GameObject化さえ済んでいれば追加コードはほぼ要りません。 

// Game::Initialize() の末尾
gizmoTargets_ = {
    &cubeObject_, &sphereObject_, &triangleObject_, &floorObject_,
    &sprite3DObject_, &modelObject_, &fbxModelObject_,
};

"Gizmo" パネルのコンボボックスは gizmoTargets_ を走査して 各 GameObject::name を選択肢として表示します。新しいオブジェクトをこの配列に 追加するだけで、コンボにも自動的に出るようになります（enum やスイッチ文を手で増やす必要はありません）。

PointLight / SpotLight は特別扱い：ライトは SceneLight という 別クラスのプロパティで、GameObjectを持ちません。lightGizmoScratch_ という 一時的な Transform をライトの現在値と行き来させる橋渡し役として使っており、 ドラッグ操作後は SceneLight の Setter（SetPointPosition 等）を 経由して書き戻します。GetData() の参照を直接書き換えると GPU に反映されないため、 ライト関連の値を変えるときは必ず Setter を使ってください。

あえて GameObject 化していないもの

対象理由
gridCubes_（負荷テスト用の大量Cube、最大 13 万個規模） 1個ずつ GameObject にすると、生成コスト・ヒープ確保・vtable経由の 呼び出しオーバーヘッドが数万倍に膨らみ破綻する。フラストラムカリングや WorldInverseTranspose のキャッシュのような「大量インスタンス専用の最適化」とも 相性が悪いため、今後も std::vector<Transform> + 共通パラメータの ままにする方針。
bgm（BGM再生用の Sound） Transform（位置・回転・スケール）という概念自体を持たない グローバルなオーディオストリームのため、そもそも GameObject の対象にならない。
PointLight / SpotLight SceneLight は「シーンに1つだけ」という前提の単一グローバルオブジェクトで 設計されている。複数光源に対応するにはこの構造自体の作り替えが必要になり、 GameObject 化とは別の大きな作業になるため、今回は対象外。

よくあるハマりどころ

Q. GetComponent<T>() が nullptr を返す

A. AddComponent<T>() を呼び忘れているか、型を間違えています。 GameObject は「コンポーネントを持っているはず」という前提で書かれているコードが 多いため、Initialize() で必ず対応するコンポーネントを追加してください。

Q. テクスチャを切り替えたのに描画に反映されない

A. コンポーネントは TextureHandle（実際のGPUハンドル）を持ちますが、 ImGui のテクスチャ選択コンボは textures_ 配列への「インデックス」（int）を 扱います。コンボで選んだ index から textures_[index].handle を引いて、 明示的に xxxRender->textureHandle = textures_[index].handle; と代入し直す必要があります（自動では同期しません）。

Q. Cube と Floor で同じ CubeRenderComponent を使っているのに、片方だけ色が変わる

A. それが正しい挙動です。cubeObject_ と floorObject_ は 別々の GameObject インスタンスであり、それぞれが自分専用の CubeRenderComponent インスタンスを持っています。クラスが同じでも インスタンスは独立しているため、一方の変更がもう一方に影響することはありません。

Q. UpdateGizmo() でドラッグしたのに描画に反映されない

A. Game::Render() 内で UpdateGizmo(view, proj) を呼ぶタイミングと、 各オブジェクトの Draw() を呼ぶタイミングの順序に注意してください。 ギズモが GameObject::transform を書き換えた「後」に Draw() が 呼ばれる順序になっていないと、その回のフレームには反映されません （現状の実装ではこの順序が正しく保たれています）。
